# 週刊4コマの共通テンプレートと公開手順

## 基準と公開方法

一覧の基準は第7話のカード寸法・切り抜き、個別ページの枠組みは第7話。`comics/templates/` は main の
`0fafc31` にある第7話個別ページの構成・CSS・ヘッダー・CTAをもとに作成した。
現在の公開サイトとの実表示照合は、必ず更新のたびに行う。
このテンプレートはビルドシステムの導入ではなく、既存の静的HTMLを生成する更新用ツール。
公開方法は引き続き main のルートから GitHub Pages。新しい公開サービスを使わない。

- 一覧: `.card > a > .thumb > img`。作品画像を幅100%・高さautoで表示し、
  上端から既存の `.thumb` で切り抜く。高さはPC 235px、680px以下215px。
  画像自体をトリミング・変形・生成しない。個別ページへ直接リンクする。
- 個別: 第7話と同じ `.full`（最大860px）、`.comic-art` の枠を使う。
  第0〜5話と同じローカル画像の直接掲載にそろえ、Xへのアクセスや埋め込みに依存させない。
  原画像は幅100%・高さautoで全体表示し、クリックで原寸ファイルを開く。
- 元投稿リンク、公開日、タグ、説明文、ことねや式CTA、X・LINEの導線、前後ナビを保つ。
- 作品画像の取得・照合ができなければ公開を止め、不足ファイルを報告する。
  キャラクター共通画像、「原画はXから」の代替表示、未確認の画像URLで埋めない。
  X投稿の埋め込みURLだけでは作品画像の取得・照合を完了したことにはしない。

## ファイル

- `templates/episode.html.tmpl`: 個別ページ全体。第7話のCSSを保持。
- `templates/card.html.tmpl`: 一覧カード。独自のサイズ・インライン装飾を追加しない。
- `templates/figure.html.tmpl`: 原画像の直接掲載、公開日と元投稿リンク。
- `metadata/NNN.json`: 話数別の確定データ。
- `../scripts/render-comic.py`: 共通テンプレートから個別HTMLとカード断片を生成。
  Python 3 と Pillow が必要。公開HTMLを直接変更せず、出力はリポジトリ外に限定する。
  不足画像、実寸不一致、未照合フラグのままでは生成を拒否する。

## 1. 更新前に公開サイトとmainを照合する

1. 作業ツリーの既存編集を保全し、`git fetch origin` で最新mainを取得する。
2. 公開サイトの `/comics/` と直前話の `/comics/NNN/` を開き、
   mainのHTML・CSS・画像URL・元投稿URLと照合する。
3. 最新mainのPagesデプロイが成功していることも確認する。
   HTMLの取得失敗を「公開内容が一致した」と扱わない。
4. PC・スマホで直前話の画像サイズ、上端の切り抜き、複数画像の掲載順、
   一覧→個別→元投稿、前後ナビ、LINEの挙動を記録する。

## 2. 公式画像とメタデータを確定する

1. ユーザーの添付原画像、または公式X投稿で、話数・題名・全画像の枚数と順序を確認する。
   公開日は既存の確定データと元投稿を照合する。
   元投稿URLは追跡クエリを除いた `https://x.com/kotoneya29/status/数字` を保存する。
2. 添付ファイルを受け取るか、投稿の各画像を公式配信元から取得し、改変せず
   `assets/comics/NNN-01.jpg`、`NNN-02.jpg` 等へ保存する。
   実際の画像形式に合う拡張子にする。既存画像の上書きはしない。
3. 画像の内容・文字・全コマ・順番・個人情報の有無を確認する。
   一覧には従来と同じ作品の先頭画像を使用し、実寸を記録する。
4. 話数別JSONに `images` を記録する。各項目は以下の形:

   ```json
   {
     "file": "assets/comics/NNN-01.jpg",
     "source_url": "実際に取得した https://pbs.twimg.com/media/... の完全URL",
     "width": 取得画像の実幅,
     "height": 取得画像の実高さ
   }
   ```

   上記は公式Xから取得する場合の説明用。URL・寸法は実際の値に置き換える。
   添付ファイルの場合は `source_url` の代わりに `"source": "user-upload"`、
   `"original_filename": "元ファイル名"`、`"sha256": "原ファイルのSHA-256"` を記録する。
   添付原画像をそのままコピーし、SHA-256が一致することを確認する。
   `thumbnail_index` は一覧に使う画像の0始まりの番号。
   全画像の目視照合後にだけ `artwork_verified` を `true` にする。
   `next_episode` は次話が公開済みの場合のみ指定する。
   タイトル・要約・説明は元投稿と既存の承認済み内容を確認して記録する。

## 3. 共通テンプレートから生成・反映する

リポジトリのルートで実行する（第8話の例）:

```sh
python scripts/render-comic.py comics/metadata/008.json --output /workspace/work/comic-008
```

1. 生成HTMLと第7話を比較し、本文・話数・画像・リンク以外の意図しない差分がないか確認する。
2. 生成した `index.html` を `comics/008/index.html` へ配置する。
3. `card.html` のカードで `comics/index.html` の該当カードを置き換える。
   同じ話を重複追加しない。既存の他話の作品画像を共通キャラクター画像に置換しない。
4. 一覧のOGPを最新の作品画像へ更新し、CollectionPageの `hasPart` を整える。
5. 前話の「次の話」、当話の「前の話」と一覧リンクを確認する。
6. `sitemap.xml` に当話のcanonicalを一度だけ追加する。
7. TOPの最新話導線やNEWSがある場合だけ、既存の方式で更新する。
   既に登録済みのNEWSを重複追加しない。公開日は確定日だけを使う。

## 4. 公開前の表示確認

- ローカルHTTPサーバーからPC・スマホで一覧と個別ページを開く。
- 一覧の先頭画像が実際の当話で、直前話と同じサイズ・上端の切り抜きであること。
- 一覧カード全体・「この4コマを読む」が正しい個別ページへ移動すること。
- 個別ページで全ての作品画像と文字を読めること。画像が実際に読み込まれ、
  原画像と一致すること。Xリンクだけの状態を「掲載確認済み」にしない。
- Xボタンが当話の公式投稿へ移動し、LINE・ことねや式・前後ナビも従来どおり動くこと。
- OGP・canonical・構造化データ・sitemapの当話番号と画像が一致すること。
- 画像404、横はみ出し、JavaScriptエラーがないこと。

## 5. 既存の方法で公開し、実際の公開URLを検証する

1. 差分を確認し、関係ないページ・プレビュー・他話の作品を変えていないことを確認する。
2. mainが進んでいれば最新を取り込み、必要な検証をやり直す。強制pushはしない。
3. 変更をコミットし、`git push origin HEAD:main` で既存mainへ反映する。
4. 当該コミットの `pages build and deployment` が成功するまで確認する。
5. キャッシュの影響を避け、新規ブラウザコンテキストで公開 `/comics/`、当話の個別URL、
   作品画像URLを開き、HTTP成功・内容・画像読込・リンク・PC/スマホ表示を確認する。
6. デプロイ成功と公開サイトでの実表示確認を区別して報告する。
   実表示が確認できなければ「公開確認済み」とせず、残った制約を報告する。

どちらも1122×1402px。添付元の名前とSHA-256は各話のmetadataに記録している。
